## 4. B10 — benchmark retention. Half-done, and READ THIS BEFORE TRUSTING ANY NUMBER

*Does obfuscation tuning cost general coding ability?* New module `src/obtune/bench_retention.py`.
MBPP+ is primary (399 tasks, 0/399 in our corpus); HumanEval+ is secondary and **contaminated**
(74/164 of its problems are in our train split).

**Three extraction faults were found, each of which reads as catastrophic forgetting:**
1. a leading space → `IndentationError` on line 1;
2. a fence opened as ```` ``` ```` + space, which the Markdown regex misses;
3. CodeLlama's `[PYTHON] ... [/PYTHON]` tags, which no Markdown regex finds.

All three share a shape worth carrying: **fine-tuning on output prediction changes how a model
frames an answer, so the arms that should show forgetting are exactly the arms that defeat the
extractor, and the untuned control never does.** Fault 3 biases the other way and deflates the
control. Assume any extractor is biased against the treatment arm until shown otherwise.

`extract_code` now tries an ordered set of readings and **accepts one only if it compiles**.
Every generation is saved to `results/retention/raw/*.jsonl`, so an extractor change is a
re-scoring job, not a GPU job:

```bash
python scripts/analysis/85_rescore_retention.py          # rewrites the JSONs, prints before/after
python scripts/analysis/85_rescore_retention.py --dry-run
```

**Status: 6 of 8 models × 2 benchmarks complete** (72 cells). Result so far, CodeLlama-34B/MBPP+:
`tuned_L0` and `merge_ties` at or above base; `mono_all` ~19 points down by emitting no function
at all on 42 % of tasks. **One model is one data point — do not quote this until the panel is
complete and `85_rescore_retention.py` has been run over everything.**

## 7. Running anything on Juno from here

No agent on the cluster. `ssh` in yourself and submit:

```bash
source scripts/env.sh
python scripts/slurm/submit.py --name <job> --partition h100 --gres gpu:1 \
  --cpus 16 --mem 96G --time 05:00:00 --argv -m obtune.bench_retention --model <m> --benchmark mbpp
```

`h100` and `a30` carry **no QoS** and are unlimited. `h200`/`normal` share one juno QoS pool with
`MaxJobsPU=4` across **both projects on this account**; `configs/compute.yaml::share_limits` is
the agreement and `submit.py` enforces it. It is currently set to **2** for the retention round —
**return it to 0** when that round is done.
